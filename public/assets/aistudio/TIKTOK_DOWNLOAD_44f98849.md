این سند فقط مسیر فنی دانلود تیک‌تاک را توضیح می‌دهد: لینک‌ها چطور شناسایی و نرمال می‌شوند، محتوا چطور گرفته می‌شود و فایل‌های به‌دست‌آمده چطور دسته‌بندی و ارسال می‌شوند.

- [tiktok_downloader.py](tiktok_downloader.py) — دانلود واقعی، مرتب‌سازی فایل‌ها، ساخت کپشن و واکشی پروفایل

## ۱. شناسایی لینک

الگوی اصلی در [main.py:63](main.py:63) تعریف شده است:

```python
TIKTOK_LINK_PATTERN = r"https?://(?:vm|vt|www)\.tiktok\.com/\S+"
```

یعنی فقط سه دامنه پذیرفته می‌شوند:

| دامنه | نوع | نمونه |
|---|---|---|
| `vm.tiktok.com` | لینک کوتاه اشتراک‌گذاری | `https://vm.tiktok.com/ZMabc123/` |
| `vt.tiktok.com` | لینک کوتاه (نسخه وب) | `https://vt.tiktok.com/ZSabc123/` |
| `www.tiktok.com` | لینک کامل | `https://www.tiktok.com/@user/video/7300000000000000000` |

نکته‌های مهم در تشخیص:

1. الگو `\S+` است، پس لینک می‌تواند هرجای متن پیام باشد، نه فقط ابتدای آن.
2. `?` در `https?` یعنی هر دو حالت `http` و `https` قبول است.
3. زیردامنه‌های دیگر (مثل `m.tiktok.com`) و دامنه‌های کوتاه‌کنندهٔ ثالث پذیرفته نمی‌شوند.
4. پس از استخراج، کاراکترهای پایانی معمول با `rstrip('.,!?)]\'"')` حذف می‌شوند تا لینک‌هایی که داخل پرانتز یا نقل‌قول آمده‌اند درست خوانده شوند ([main.py:3736](main.py:3736)).

پس از پیدا شدن لینک، بررسی‌های دسترسی انجام می‌شود (کاربر مسدود نباشد و شرایط عضویت رعایت شده باشد) و سپس پردازش ادامه پیدا می‌کند.

## ۲. نرمال‌سازی لینک کوتاه

لینک‌های `vm.` و `vt.` باید به لینک کامل تبدیل شوند، چون فقط لینک کامل (`/@user/video/<id>`) قابل دانلود مستقیم است. این کار در ابتدای `download_tiktok_filtered` انجام می‌شود ([tiktok_downloader.py:53](tiktok_downloader.py:53)):

```python
resp = requests.head(url, allow_redirects=True, timeout=10,
                     headers={"User-Agent": "Mozilla/5.0"})
resolved = resp.url
```

مراحل دقیق:

1. یک درخواست `HEAD` با دنبال‌کردن ریدایرکت‌ها (`allow_redirects=True`) زده می‌شود و آدرس نهایی از `resp.url` خوانده می‌شود.
2. این فراخوانی مسدودکننده (blocking) است، پس با `loop.run_in_executor(None, _resolve)` به یک thread جداگانه منتقل می‌شود تا حلقهٔ asyncio قفل نشود.
3. اگر آدرس نهایی به صفحهٔ **login** ریدایرکت شده باشد (`"login" in parsed.path`)، پارامتر `redirect_url` از query string استخراج و با `unquote` دیکد می‌شود. سپس پارامترهای اضافی `_r` و `_t` با regex حذف می‌شوند:

   ```python
   clean = re.sub(r'[?&](_r|_t)=[^&]*', '', clean).rstrip('?&')
   ```

   این کار جلوی ریدایرکت اجباری به صفحهٔ ورود را می‌گیرد و لینک واقعی پست را برمی‌گرداند.
4. اگر خطایی رخ دهد (timeout، خطای شبکه، ریدایرکت نامعتبر)، فقط یک warning ثبت می‌شود و با همان لینک کوتاه اصلی ادامه داده می‌شود — یعنی شکست در resolve باعث شکست دانلود نمی‌شود.

## ۳. تشخیص نوع لینک (پست یا پروفایل)

بعد از نرمال‌سازی، نوع لینک با دو regex مشخص می‌شود ([main.py:3767](main.py:3767)):

```python
is_post    = bool(re.search(r"/@[A-Za-z0-9_.\-]+/(?:video|photo)/", video_url))
is_profile = bool(re.search(r"/@(?P<u>[A-Za-z0-9_.\-]+)(?:[/?]|$)", video_url)) and not is_post
```

| حالت | شرط | مسیر پردازش |
|---|---|---|
| **پست** | مسیر شامل `/@user/video/` یا `/@user/photo/` | جریان دانلود رسانه |
| **پروفایل** | مسیر شامل `/@user` و بعد از آن `/` یا `?` یا پایان رشته | واکشی اطلاعات پروفایل (بدون دانلود رسانه) |
| **نامشخص** | هیچ‌کدام | fallback به جریان دانلود |

در حالت پروفایل، نام کاربری با همان regex استخراج و به `fetch_tiktok_profile` داده می‌شود؛ سپس اطلاعات حساب (نام، یوزرنیم، بیو، آمار) به‌همراه عکس پروفایل ارسال می‌شود. هیچ ویدیویی در این مسیر دانلود نمی‌شود.

## ۴. دانلود فایل با gallery-dl

قلب فرآیند یک فراخوانی ساده از ابزار خط فرمان `gallery-dl` است ([tiktok_downloader.py:92](tiktok_downloader.py:92)):

```python
command = ["gallery-dl", "-d", output_dir, url]
result = await loop.run_in_executor(
    None,
    lambda: subprocess.run(command, capture_output=True, text=True, check=True)
)
```

جزئیات:

- `-d output_dir` پوشهٔ مقصد را تعیین می‌کند؛ `gallery-dl` بسته به نوع پست، زیرپوشه هم می‌سازد.
- پوشهٔ کاری برای هر کاربر جداگانه ساخته می‌شود: `output_dir = f"{user_id}"` و در صورت نبود با `os.makedirs` ایجاد می‌شود.
- اجرای `subprocess` مسدودکننده است، بنابراین با `run_in_executor` در thread جدا اجرا می‌شود و حلقهٔ async آزاد می‌ماند.
- `check=True` یعنی کد خروج غیرصفر به `CalledProcessError` تبدیل می‌شود و به مسیر خطای اختصاصی می‌رود.
- اگر `gallery-dl` نصب نباشد یا در PATH نباشد، `FileNotFoundError` گرفته می‌شود و خطای متناظر برگردانده می‌شود.
- هر پست تیک‌تاک ممکن است بیش از یک فایل بدهد (ویدیو + کاور + صوت)، پس با یک فراخوانی چند فایل ذخیره می‌شوند.

> نکته: هیچ API رسمی یا اسکرپ مستقیم HTML برای دانلود رسانه استفاده نمی‌شود؛ کل مسیر رسانه به `gallery-dl` سپرده شده است. نسخهٔ حداقلی در [requirements.txt](requirements.txt) برابر `gallery-dl>=1.28.0` است.

## ۵. جمع‌آوری و مرتب‌سازی فایل‌ها

پس از پایان `gallery-dl`، همهٔ فایل‌های پوشه با `os.walk` (بازگشتی، شامل زیرپوشه‌ها) لیست می‌شوند و برای هر فایل دو کار انجام می‌شود ([tiktok_downloader.py:104](tiktok_downloader.py:104)):

```python
for idx, f in enumerate(files, 1):
    original_path = os.path.join(root, f)
    new_filename = f"{idx}{os.path.splitext(f)[1]}"
    os.rename(original_path, new_path)
    original_filenames[new_filename] = f     # نگه‌داشتن نام اصلی
```

1. **تغییر نام ترتیبی**: هر فایل به `<شماره><پسوند>` تغییر نام می‌دهد (`1.mp4`، `2.jpg`، ...). این کار برای جلوگیری از خطاهای نام فایل طولانی یا کاراکترهای غیرمجاز در نام‌های اصلی `gallery-dl` است.
2. **نگه‌داشتن نام اصلی در حافظه**: نگاشت `original_filenames` بعداً برای ساختن کپشن استفاده می‌شود، چون نام اصلی معمولاً همان کپشن/عنوان پست است.

سپس فایل‌ها بر اساس پسوند فیلتر می‌شوند ([tiktok_downloader.py:113](tiktok_downloader.py:113)):

```python
supported_media_extensions = (".jpg", ".jpeg", ".png", ".webp", ".mp4", ".mp3")
```

- `image_files`: پسوندهای `.jpg .jpeg .png .webp`
- `video_files`: `.mp4`
- `audio_files`: `.mp3`
- هر فایل با پسوند دیگر (متادیتا، `json`، `txt` و ...) با `os.remove` حذف می‌شود.

از آنجا که تغییر نام قبل از فیلتر انجام می‌شود، شماره‌گذاری فایل‌های باقی‌مانده ممکن است پیوسته نباشد (مثلاً `2.mp4` و `4.jpg`)؛ این طبیعی است و مشکلی ایجاد نمی‌کند.

## ۶. ساخت کپشن

تابع `extract_caption` برای هر فایل اجرا می‌شود ([tiktok_downloader.py:118](tiktok_downloader.py:118)):

1. نام اصلی فایل از نگاشت `original_filenames` بازیابی می‌شود.
2. پسوند حذف می‌شود و الگوی نام `gallery-dl` پاک‌سازی می‌شود:

   ```python
   clean_caption = re.sub(r'^\d+(_\d+)?\s*|\s*\[[a-f0-9]{32}\]\s*', '', base_name).strip()
   ```

   - `^\d+(_\d+)?\s*` ← شمارهٔ ابتدای نام (مثل `7301234_1 `)
   - `\s*\[[a-f0-9]{32}\]\s*` ← شناسهٔ ۳۲ کاراکتری هگز داخل براکت (هش پست)

3. اگر بعد از پاک‌سازی چیزی نماند، یک متن پیش‌فرض جایگزین می‌شود.
4. طول کپشن به ۷۵۰ کاراکتر محدود می‌شود تا از سقف مجاز کپشن (۱۰۲۴) عبور نکند.
5. نام سازنده از لینک استخراج می‌شود:

   ```python
   creator_match = re.search(r'/@([A-Za-z0-9_.\-]+)/', original_url)
   ```

6. ساختار نهایی کپشن، به ترتیب:
   - خط «Downloaded by» با نام و شناسهٔ دانلودکننده (در صورت وجود) داخل بلوک نقل‌قول
   - خط `👤 Creator: @username` (اگر استخراج شده باشد)
   - خط `🔗 Video Link` به‌صورت هایپرلینک روی آدرس اصلی پست
   - خط `📜 <کپشن پاک‌شده>` و بعد از آن یک خط جداکننده
   - خط برندینگ ثابت پروژه

تمام متن‌ها با `html.escape` امن‌سازی می‌شوند و برای راست‌به‌چپ درست، ابتدای خطوط با کاراکتر LRM (`‎`) شروع می‌شوند.

## ۷. ارسال محتوا (سه سناریو)

پس از دسته‌بندی فایل‌ها، سه مسیر وجود دارد. تصویر و ویدیو با هم رقابت دارند (ویدیو فقط در نبود تصویر ارسال می‌شود)، اما صوت مستقل است و در هر حالتی ارسال می‌شود.

### الف) تصویر (آلبوم)

- تصاویر در دسته‌های ۸تایی ارسال می‌شوند.
- **کپشن فقط روی آیتم اول هر آلبوم** قرار می‌گیرد (`position == 0`) تا تکرار نشود.
- یک پیام وضعیت با شمارنده و نوار پیشرفت (`██████░░░░`) ساخته می‌شود و پس از هر گروه ویرایش می‌شود:

  ```python
  bar = "█" * filled + "░" * (10 - filled)
  ```
- بین گروه‌ها ۱ ثانیه تأخیر (`asyncio.sleep(1)`) فقط وقتی حداقل ۵ آیتم دیگر مانده باشد.
- تابع `send_media_group_fixed` خطاهای شناخته‌شده (متن خطای شامل `topics` یا `required keyword-only argument`) را **موفق** در نظر می‌گیرد و بقیهٔ خطاها را نادیده می‌گیرد و **هیچ‌وقت fallback به ارسال تکی نمی‌کند** — دلیلش جلوگیری از ارسال تکراری فایل‌هاست.

### ب) ویدیو

- فقط وقتی اجرا می‌شود که **هیچ تصویری** وجود نداشته باشد: `if video_files and not image_files`.
- فقط **اولین** فایل mp4 (`video_files[0]`) ارسال می‌شود.
- قبل از ارسال، پیام وضعیت «در حال آماده‌سازی و ارسال فایل» نمایش داده می‌شود.

### ج) صوت

- برای هر فایل mp3 جداگانه ارسال می‌شود و هر کدام کپشن خودش را دارد.
- این بخش مستقل از ویدیو اجرا می‌شود (شرط `not image_files` ندارد).

### حالت خطا (هیچ فایل معتبری نبود)

اگر هر سه لیست خالی باشند (یعنی همهٔ فایل‌ها فیلتر شده باشند)، پیام خطای «محتوای تیک‌تاک پیدا نشد» برگردانده می‌شود و نتیجه `False` است.

### نکتهٔ رفتاری مهم

اگر یک پست هم تصویر و هم ویدیو داشته باشد، **فقط آلبوم تصاویر ارسال می‌شود** و ویدیو ارسال نمی‌شود؛ چون شرط بخش ویدیو `and not image_files` است. این رفتار عمدی است تا پست‌های عکسی که `gallery-dl` برایشان کاور mp4 هم می‌گیرد، به‌جای یک ویدیوی یک‌قابی، آلبوم درست بفرستند.

## ۱۰. خطاها و پاک‌سازی

سه نوع خطای اصلی جداگانه مدیریت می‌شوند ([tiktok_downloader.py:342](tiktok_downloader.py:342)):

## ۱۱. واکشی پروفایل (مسیر جدا از دانلود)

`fetch_tiktok_profile` چهار لایه fallback دارد ([tiktok_downloader.py:414](tiktok_downloader.py:414)):

1. **`__UNIVERSAL_DATA_FOR_REHYDRATION__`** — بلاک JSON داخل HTML صفحه با regex استخراج و `json.loads` می‌شود؛ مسیر داده‌ها:

   ```
   __DEFAULT_SCOPE__ → webapp.user-detail → userInfo → { user, stats }
   ```

   و از آن `uniqueId, nickname, signature, avatarLarger, verified, secret, followerCount, heartCount, videoCount` برداشته می‌شود. این بهترین منبع است چون همهٔ فیلدها یک‌جا دارد.

2. **`gallery-dl -j <url>`** — خروجی JSON متادیتا؛ گاهی آرایه است و گاهی JSON خط‌به‌خط. هر دو حالت پشتیبانی می‌شود: اگر کل خروجی آرایه باشد مستقیم پارس می‌شود، وگرنه هر خط جداگانه `json.loads` می‌شود. سپس فیلدها از همهٔ entryها با `setdefault` تجمیع می‌شوند (اولین مقدار غیرخالی برنده است).

3. **`SIGI_STATE`** — بلاک JSON قدیمی‌تر صفحه؛ `UserModule.users` و `UserModule.stats` پارس می‌شوند.

4. **متا تگ‌ها** — ساده‌ترین لایه: `og:title` (نام + `(@username)`)، `og:image` (عکس پروفایل)، `name="description"` (بیو).

همهٔ این‌ها blocking هستند، به همین دلیل کل تابع `_sync_fetch` یک‌جا با `run_in_executor` در thread جدا اجرا می‌شود.

بعد از واکشی، عکس پروفایل با `requests.get` (در `download_url_bytes`، هم در thread جدا) گرفته می‌شود و به‌صورت `BytesIO` با نام `profile.jpg` ارسال می‌شود؛ اگر ارسال عکس شکست بخورد، فقط متن آمار پروفایل فرستاده می‌شود (fallback دو مرحله‌ای).

## ۱۲. خلاصهٔ جریان کامل

```
پیام حاوی لینک
   │
   ├─ regex: https?://(?:vm|vt|www)\.tiktok\.com/\S+   →  پیدا شد؟
   │      └─ نه → پیام نادیده گرفته می‌شود
   │
   ├─ rstrip علائم پایانی
   ├─ بررسی مسدود بودن کاربر و شرایط عضویت
   ├─ semaphore(10)
   │
   ├─ resolve لینک کوتاه (HEAD + redirect)
   │      └─ ریدایرکت به login → استخراج redirect_url و حذف _r/_t
   │
   ├─ classify
   │    ├─ post    → دانلود رسانه
   │    ├─ profile → fetch_tiktok_profile (۴ لایه fallback) → ارسال کارت پروفایل
   │    └─ other   → دانلود رسانه
   │
   └─ دانلود رسانه
        ├─ gallery-dl -d <user_id> <url>   (در executor)
        ├─ rename → 1.ext, 2.ext, ...
        ├─ filter → jpg/jpeg/png/webp | mp4 | mp3  (بقیه حذف)
        ├─ caption از نام اصلی + سازنده + لینک
        ├─ آلبوم ۸تایی تصاویر (کپشن روی اولی)
        │    ├─ نبود تصویر + وجود mp4 → ارسال اولین ویدیو
        │    └─ mp3ها جداگانه
        ├─ add_download(..., status, type, "tiktok")
        └─ finally: shutil.rmtree(output_dir)
```

## ۱۳. پیش‌نیازها و نکات عملیاتی

- **`gallery-dl` باید در PATH باشد**؛ وگرنه همهٔ دانلودها با `FileNotFoundError` شکست می‌خورند. در Dockerfile فقط پایتون و ابزارهای سیستمی نصب می‌شوند و `gallery-dl` از طریق `requirements.txt` نصب می‌شود (پکیج پایتون، اما entry point خط فرمان هم می‌سازد).
- **`ffmpeg`** در Dockerfile نصب است؛ `gallery-dl` برای ادغام/تبدیل برخی رسانه‌ها به آن نیاز دارد.
- **کوکی تیک‌تاک** جایی در کد وجود ندارد — برخلاف اینستاگرام، دانلود تیک‌تاک بدون احراز هویت انجام می‌شود. یعنی پست‌های خصوصی، پست‌های نیازمند ورود یا محتوای محدود جغرافیایی قابل دانلود نیستند.
- **`yt-dlp`** در مسیر تیک‌تاک استفاده نمی‌شود؛ فقط پینترست از آن برای استریم HLS استفاده می‌کند.
- **پوشهٔ خروجی** با نام `<user_id>` در پوشهٔ کاری فعلی ساخته می‌شود. اگر ربات با چند process موازی اجرا شود، این نام‌گذاری می‌تواند تصادم ایجاد کند؛ برای یک process، `finally` تضمین می‌کند پوشه پاک شود.
- **هیچ محدودیت حجم/مدت** در کد برای ویدیو اعمال نمی‌شود؛ محدودیت واقعی سمت سرور آپلود است، نه این کد.
